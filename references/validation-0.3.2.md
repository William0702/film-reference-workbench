# 0.3.2 跨账号权限修复与复测（2026-10-21）

## 根因与变更

实际 ACL 证据：0.3.1 的 python-packages 根目录启用了 DACL 保护，只有 OWNER RIGHTS、SYSTEM、Administrators；runtime 父目录原本已允许测试沙箱账号 Modify。Python 3.12 的临时目录权限经移动保留，造成父目录可访问而依赖目录不可读。

- 新生成 staging 和 self-test 目录继承 runtime 已有权限；pip 安装结束后，依赖树启用父 ACL 继承，再验证版本及 native import，最后激活目录。
- 原受保护目录可由安装账号运行新版 setup 自动修复；完成记录随依赖保存，后续使用账号无需反复请求 WRITE_DAC。
- 权限操作只允许 python-packages 或 packages-stage-* 直接子目录，拒绝重解析点；不增加任何用户/组授权，不修改系统目录、全局 ACL 或执行策略。
- 处理长路径，目录激活遇到 Windows 短暂锁时有限重试，持续失败仍报错且保留现场。
- updater 只在当前 Git 命令信任本技能目录，解决跨所有者 checkout 的安全目录检查；不修改全局 Git 配置。

## 测试范围与发布顺序

为满足“通过后同步 Git”，跨账号安装/快进测试从未发布的本地候选 Git 仓库拉取，origin 字段保留正式仓库地址，通过测试进程专用 URL 映射到候选目录。工具、wheel 与模型仍真实联网下载。此处本地 Git 更新通过不等于沙箱账号已验证 GitHub 登录态或网络；此前 GitHub 冷安装网络测试见 0.3.1 记录。

仍共用主机 Windows、既有 Python 3.12 基础解释器及 Git，未测试缺 Python 的 winget 分支或全新 Windows 虚拟机。不授予原本没有 runtime 父目录权限的账号访问权；只读账号不承诺能写入日志、更新代码或模型。真实影片分析质量和浏览器界面不属于本次安装自检范围。

首次重测曾遇到长路径和目录激活访问拒绝，保留失败日志后修复再测；只将最终成功结果记为通过。
